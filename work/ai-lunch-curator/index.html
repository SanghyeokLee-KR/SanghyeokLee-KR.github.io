01개요

사람이 손대지 않아도, 매주 메뉴가 모이고 매일 아침 점심이 도착합니다

매주 월요일 GitHub Actions가 학교 식단표를 모으고, AI가 메뉴를 정리해 DB에 쌓습니다. 평일 아침에는 그날 점심이 Teams로 옵니다. 웹에서는 오늘의 점심과 지난 점심, 자주 나온 메뉴를 볼 수 있습니다.

과제의 출발은 세 가지 질문이었습니다. GitHub Actions로 일정에 맞춰 작업을 돌릴 수 있는가, Python으로 식단표를 긁어 올 수 있는가, 오늘 메뉴를 웹훅으로 보내는 봇을 만들 수 있는가. 셋을 모두 만들고, 그 위에 AI 분석과 웹·DB, 그리고 테스트를 통과해야만 이어지는 배포를 더했습니다.

02자동으로 도는 흐름

수집도, 발송도, 배포도 GitHub Actions가 문을 두드리면 시작됩니다

앱은 스스로 시계를 보지 않습니다. GitHub Actions가 정해진 시각에 토큰을 붙여 수집 주소와 발송 주소를 부르고, 코드가 올라오면 시험을 거쳐 배포합니다. 아래에서 장면을 고르면 각각이 어떤 길을 지나는지 볼 수 있습니다.

저장소의 배포 구조도와 시퀀스 다이어그램을 옮겨 그렸습니다. 운영 기간이 끝난 뒤에는 EC2를 내렸고, 지금은 스케줄을 꺼 두었습니다. 원본 구조도 보기

03배포 · EC2 한 대와 Nginx

밖에서 닿는 곳은 Nginx의 80번 하나로 좁혔습니다

EC2(Ubuntu, t3.small) 위에 docker compose로 앱과 Oracle XE를 올렸습니다. 앱의 8000번은 127.0.0.1에만 묶어 밖에서 직접 닿지 않게 하고, 앞에 둔 Nginx가 80번으로 받아 넘깁니다. 보안 그룹은 22번과 80번만 열어, 8000번이나 DB 포트 같은 안쪽 포트는 밖에서 보이지 않습니다.

  1. 통계를 위해 메뉴를 나눠 저장했습니다메뉴를 한 칸에 묶어 두지 않고 요리 하나씩 MENU_ITEM에 나눠 담아, 자주 나온 메뉴를 GROUP BY로 바로 셀 수 있게 했습니다.
  2. 다시 돌려도 겹치지 않습니다날짜 기준 MERGE로 저장해, 같은 날을 다시 수집해도 중복 없이 갱신됩니다.

03-2배포하며 풀어 낸 문제

서버에 올리는 길에서 막힌 곳을 하나씩 풀었습니다

배포까지 가며 막혔던 곳과 해결6건 펼쳐 보기
  1. 메모리

    t3.micro에서는 Oracle XE가 뜨지 않았습니다

    메모리 1GB로는 모자라, 인스턴스를 t3.small(2GB)로 바꾸고 스왑 2GB를 잡았습니다.

  2. 디스크

    루트 디스크 8GB가 모자랐습니다

    Oracle 이미지만 2.5GB쯤이라, EBS 볼륨을 30GB로 늘렸습니다.

  3. 포트

    호스트의 1521번을 다른 Oracle이 쓰고 있었습니다

    컨테이너는 1522번으로 비켜 연결했습니다.

  4. 권한

    Nginx가 정적 파일을 직접 읽지 못했습니다

    /home/ubuntu 아래의 권한 때문이었습니다. 정적 파일도 앱으로 넘기도록 바꿨습니다.

  5. 시간대

    평일 아침 알림에 전날 메뉴가 떴습니다

    EC2가 UTC로 돌아서, 한국의 이른 아침에는 아직 전날이었습니다. '오늘'을 늘 한국 시간으로 계산하도록 바꿨습니다.

  6. 로컬 환경

    WSL2가 깨져 Docker 엔진이 뜨지 않았습니다

    기능을 다시 켜고 재부팅해도 풀리지 않아, 공식 WSL 설치 파일을 직접 받아 설치해 되살렸습니다.

04CI/CD · GitHub Actions

테스트를 통과해야만 서버에 올라갑니다

main 브랜치에 코드가 올라오면 먼저 pytest가 돕니다. 통과해야만 배포 작업이 이어져, SSH로 EC2에 들어가 비밀 값을 GitHub Secrets에서 .env로 만들고 docker compose로 다시 띄웁니다. 깨진 코드는 서버에 닿지 못합니다.

워크플로언제하는 일
ci.ymlpush · PRpytest. 목킹이라 비밀 값이 필요 없습니다
deploy.ymlmain push테스트 통과를 조건으로 EC2에 SSH 배포
weekly-menu.yml운영 당시 월요일 08:30토큰을 붙여 수집 주소 호출
daily-notify.yml운영 당시 평일 09:00토큰을 붙여 발송 주소 호출

시각은 모두 한국 시간입니다. 지금은 EC2를 내려 두어 스케줄을 끄고, 손으로 실행하는 단추만 남겼습니다.

  1. 시험은 바깥을 부르지 않습니다OpenAI와 Teams 호출을 모두 목킹해, 시험을 아무리 돌려도 요금이 나가거나 채널에 메시지가 가지 않습니다.
  2. 웹 없이도 돌아가는 봇수집·분석·그림·발송을 CLI 하나로도 돌릴 수 있게 만들어, GitHub Actions만으로도 동작합니다.

05비용과 보안

돈이 드는 주소는 토큰으로 잠그고, 같은 그림은 다시 만들지 않았습니다

수집 주소는 OpenAI를 부릅니다. 아무나 부를 수 있으면 요금이 새고, 웹훅 주소가 새면 채널로 아무 메시지나 갈 수 있습니다. 그래서 비밀 값은 저장소 밖에 두고, 비싼 작업은 토큰이 있어야만 시작되게 했습니다.

무엇을 막았나어떻게
키와 웹훅이 저장소에 올라가는 것.env는 추적에서 빼고, 코드에서는 환경 변수로만 읽습니다
실수로 커밋되는 것저장소를 공개하기 전에 키·웹훅·비밀번호 형태를 검색해, 추적 중인 파일에 평문이 없는 것을 확인했습니다
CI와 배포에서 새는 것GitHub Secrets로만 넣고, 배포할 때 EC2에 .env를 만듭니다
아무나 수집·발송을 부르는 것Bearer 토큰이 없으면 401입니다
앱 포트가 밖에 드러나는 것8000번은 127.0.0.1에만 묶고, 보안 그룹은 22번과 80번만 엽니다
  1. 같은 메뉴 그림은 다시 쓰기메뉴 구성을 해시로 묶어 그림 캐시 테이블에 따로 둡니다. 같은 구성이면 이미 만든 그림을 다시 써서 AI 호출을 줄입니다.
  2. 부르면 바로 답하기수집처럼 무거운 일은 백그라운드로 돌리고, 부른 쪽에는 바로 202로 답합니다.

06화면 · 웹과 Teams

오늘의 점심과 지난 30일을 그림으로 넘겨 봅니다

웹은 오늘의 점심, 지난 점심, 통계 세 화면입니다. 색과 간격은 CSS 변수로 묶어 두고 밝은 화면과 어두운 화면을 모두 지원했습니다.

07결과와 배운 점

작은 서비스라도, 사람이 없을 때 제대로 도는지가 중요했습니다

  1. 시험을 배포 앞의 문으로 두었습니다테스트를 통과해야만 배포가 이어지게 하니, 서버에 올라가는 코드는 늘 시험을 거친 코드였습니다.
  2. 돈이 드는 호출은 문 앞에서 막습니다외부 AI를 부르는 주소는 토큰으로 잠그고, 같은 결과는 캐시로 다시 썼습니다.
  3. '오늘'은 사용자의 시간으로 셉니다서버는 UTC로 돌았지만, 알림을 받는 사람은 한국 시간을 삽니다. 시간대 하나로 전날 메뉴가 갈 수 있다는 걸 직접 겪고 고쳤습니다.
