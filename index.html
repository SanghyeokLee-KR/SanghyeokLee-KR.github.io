처음에는 웹 서비스 기능을 만드는 백엔드 프로젝트를 주로 했습니다. 만든 서비스를 직접 배포하면서 서버가 죽거나 요청이 몰릴 때의 동작을 확인할 일이 많아졌고, 지금은 Linux 서버와 AWS 구성을 직접 설정한 뒤 장애를 내서 복구되는지 확인하는 작업을 주로 합니다.

이렇게 일합니다

  1. 01

    Linux 서버를 직접 설정합니다

    계정과 권한, 로그, 방화벽, 디스크를 직접 설정했습니다. RAID1에서 디스크를 빼고 교체해 봤고, 디스크 용량을 일부러 채워 경보가 오는지 확인했습니다.

  2. 02

    장애를 내서 복구를 확인합니다

    주 DB를 강제로 끄고, 예비 DB가 승격되는 동안 주문이 사라지는지 대조했습니다. 공격/방어 CTF에서는 경기 내내 채점 기준 다운이 한 번도 없었습니다.

  3. 03

    관제와 배포를 자동화했습니다

    Prometheus와 Grafana로 지표를 보고, 경보가 울리면 AI가 원인을 정리해 Teams로 보고하게 했습니다. 배포는 GitHub Actions로 자동화했습니다.

  4. 04

    백엔드도 개발합니다

    같은 주문이 두 번 들어올 때의 멱등 처리, 서버가 두 대일 때 요청 제한 카운터를 DB에서 공유하는 문제처럼 데이터가 어긋날 수 있는 부분을 테스트와 측정으로 확인하며 고쳤습니다.
