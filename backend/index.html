01 failstop · 주문 접수와 멱등성04 / 15

주문 API

같은 주문을 여러 번 다시 보내도 주문은 하나만 생깁니다

  1. 주문 키는 클라이언트가 만듭니다client_order_id가 없으면 받지 않습니다. 서버가 키를 대신 만들면, 응답을 못 받고 다시 보낼 때마다 새 주문이 생길 수 있기 때문입니다.
  2. 같은 키면 내용을 비교합니다요청 본문을 JCS(RFC 8785)로 정규화한 뒤 SHA-256으로 비교합니다. 필드 순서나 공백이 달라도 같은 주문이면 같은 값이 나옵니다.
  3. 엔진보다 저널에 먼저 기록합니다명령을 command_journal에 커밋한 다음에야 엔진에 넘깁니다. 엔진이 받은 명령은 모두 DB에 먼저 남아 있습니다.
  4. 커밋됐는지 모를 때는 DB에 다시 묻습니다기록하는 순간 연결이 끊기면, DB 함수로 저널에 실제로 들어갔는지 확인합니다. 그래도 답을 못 받으면 503을 돌려주되 주문 키는 지우지 않습니다.

01 failstop · 단일 리더와 옛 리더 차단05 / 15

앱 서버 두 대, 주문장을 바꾸는 서버는 하나

잠깐 멈췄다 돌아온 옛 리더의 쓰기를 리스와 epoch로 막았습니다

리더만 기한이 있는 리스를 쥐고, 리더가 바뀔 때마다 epoch를 1씩 올립니다. 까다로운 건 잠깐 멈췄던 옛 리더가 자기가 아직 리더라고 믿고 쓰기를 이어 가는 경우였습니다. 그래서 권한을 확인하는 일과 쓰는 일을 나누지 않고, SQL 한 문장 안에 넣었습니다.

-- 저널 기록(줄여서 옮김)
INSERT INTO command_journal (...)
SELECT ...
  FROM leader_lease
 WHERE holder = :me
   AND epoch = :epoch
   AND lease_until > clock_timestamp()
   FOR KEY SHARE;

세 조건 중 하나라도 틀리면 0행이 들어가고, 옛 리더의 쓰기는 거기서 끝납니다. 확인과 기록 사이에 틈이 없어서, 그 사이에 리더가 바뀌는 일도 생기지 않습니다.

장애 시험 중 찾아서 고친 문제

  1. DB 지연DB를 느리게만 했는데 리더가 바뀌었습니다정산 트랜잭션의 FOR SHARE가 리스 갱신을 막고 있었습니다. FOR KEY SHARE와 유일 인덱스로 바꾼 뒤, 같은 시험 세 번 모두 리더가 그대로였습니다.
  2. 연결 끊김연결이 끊기면 리더 없이 멈췄습니다트랜잭션을 연 채 멈춘 세션이 잠금을 쥐고 있었습니다. DB에 10초 제한과 keepalive를 걸자 고친 직후 시험에서 13.9초 만에 이어받았고, 이후 28회 반복에서는 길어도 13.5초였습니다.
  3. 리더 교대새 리더가 이미 끝난 리스를 받았습니다만료 시각을 잠금을 기다리기 전부터 세고 있었습니다. 잠금을 얻은 뒤부터 세도록 고치자 이어받기가 10초 안팎으로 고르게 나왔습니다.
  4. 옛 리더물러난 리더가 500을 돌려줬습니다리더가 아닌 서버는 503을 돌려주게 바꿨습니다. 그 뒤로 다시 돌린 시험에서는 주문 500이 한 건도 나오지 않았습니다.

제가 한 일 지도(위험 구역과 경로), WebSocket, Python AI 서버, 관리자 기능, 배포, 그리고 팀원과 함께 짠 Oracle 스키마. 게시판 API와 처음 수집기, 화면 퍼블리싱은 팀원이 맡았습니다.

  3. 서버를 늘려도 모두가 받도록운영 구성에서는 Kafka를 거치게 하고 서버마다 컨슈머 그룹을 따로 두어, 어느 서버에 붙은 사용자든 같은 알림을 받게 짰습니다. 평가 기간에는 서버 한 대로 돌렸습니다.

  3. 가는 길이 구역을 지나도 뺍니다점과 선분 사이의 최단거리를 계산해, 출발지에서 대피소로 가는 길이 위험 원을 가로지르는지 봅니다.

처음에는 운영 중인 대피소가 추천에 제대로 잡히지 않았습니다. 운영 여부를 '정상·영업·운영' 값으로 판단했는데, 실제 데이터에는 '사용중'으로 들어 있었습니다. '사용중'만 운영 중으로 보도록 고치고, 이 규칙을 테스트로 고정했습니다.

k6로 동시 사용자 60명까지 부하를 걸어 보니, 시설 조회 한 번이 1,500건, 387KB를 내려보내고 있었습니다. 필드별로 따지면 주소가 25.2%였는데, 지도 마커에는 주소가 필요 없었습니다. 그래서 목록 전용 DTO를 따로 만들어 주소를 빼고 응답 압축을 켰습니다.

MERGE INTO RATE_LIMIT_BUCKET b
USING (SELECT ? RATE_KEY, ? NOW_AT, ? CUTOFF_AT FROM dual) s
   ON (b.RATE_KEY = s.RATE_KEY)

      b.HIT_COUNT = CASE WHEN b.WINDOW_STARTED_AT < s.CUTOFF_AT
                         THEN 1 ELSE b.HIT_COUNT + 1 END, ...
 WHEN NOT MATCHED THEN INSERT ... HIT_COUNT = 1
